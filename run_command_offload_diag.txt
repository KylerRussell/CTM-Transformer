# ── Dual-GPU Training (NCCL, no DDP) — INSTRUMENTED VERSION ────────────
# Two patches landed vs. the previous `train_offload.py`:
#   1. Optimizer construction now goes through `_make_adamw` so
#      --use_8bit_adam actually takes effect (was previously ignored,
#      forcing fp32 moments and burning ~3.6 GB extra VRAM per rank).
#   2. PhaseTimer instrumentation around data, student_fwd, backward,
#      allreduce, grad_clip, optimizer phases on rank 0 only. Adds
#      torch.cuda.synchronize() at each phase boundary so timings are
#      real elapsed time, not just kernel-launch time.
#
# This run is for DIAGNOSIS, not production. ~200 steps with profiler
# reports every 100 steps. Once the breakdown is in hand, we'll know
# where to spend the next optimization effort.
#
# Expected report at step 100 will look something like:
#   data         ~0-1ms
#   student_fwd  ~400-450ms
#   backward     ~900-1100ms      (single-GPU was 905ms)
#   allreduce    ~150-300ms       (only fires every 8 steps; mean is
#                                   amortized, so /8 of the actual cost)
#   grad_clip    ~5-8ms
#   optimizer    ~25-50ms         (lower than before with 8-bit AdamW)
#
# If allreduce mean is ~25-40ms (i.e. actual cost ~200-300ms / 8), it's
# already well-amortized and the bottleneck is forward+backward themselves
# — the only remaining lever is something like chunked KL or a batch=2
# attempt. If allreduce mean is >100ms, the all-reduce is the bottleneck
# and we should look at view-based flattening (torch._utils._flatten_dense_tensors).
#
# To stop:

# fuser -k -9 29501/tcp && echo "Freed PyTorch distributed port" || echo "Port already free"
